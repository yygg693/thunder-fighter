## 0. 阅读指引与代码事实基线

### 0.1 本文档是什么 / 不是什么

| 是 | 不是 |
|---|---|
| 渲染无关的**玩法 + 视觉蓝图** | Three.js / WebGL 实现方案 |
| 3D 建模的**验收标准**（剪影、比例、特征件、母题） | 网格拓扑 / 材质 / 贴图规格 |

> 因此本文档凡描述「长什么样」，一律给**剪影语言 + 比例 + 特征件 + 运动语义**，不给绘制指令。3D 重平台架构由 engineering-lead 负责。

## 1. 战机皮肤系统 v2（机型化 + 各自玩法）

### 1.1 现状诊断

**问题陈述**：皮肤系统当前是「**一台战机 × 6 套配色**」，不是「6 台战机」。

| 现有皮肤 | id | 机身色 | 实际差异 |
|---|---|---|---|
| 苍蓝骑士 | `cyan_knight` | `#3d8ba3` | **有 AI 贴图**（唯一） |
| 烈焰红隼 | `crimson_falcon` | `#b05a52` | 仅换色 + `stripe` 涂装 |
| 翡翠游隼 | `emerald` | `#4f9b74` | 仅换色 + `plain` |
| 紫电惊鸿 | `violet` | `#8272ad` | 仅换色 + `hex` |
| 暗夜幽灵 | `stealth` | `#3a414f` | 仅换色 + `carbon` |
| 黄金圣翼 | `golden` | `#c9a24e` | 仅换色 + `stripe` |

三条设计层结论：

1. **命名承诺 vs 实际体验断裂**。「红隼 / 游隼 / 惊鸿 / 幽灵 / 圣翼」是五种截然不同的动物学 / 战术意象，玩家的期待被名字拉到了「机型」层级，实际拿到的是色板。这是最廉价的失望。
2. **没有选择的选择**。皮肤选择界面看起来是个决策点，但它不影响任何一次开火、任何一次走位。按 SDT，这是**假自主感** —— 比没有选择更伤。
3. **`cyan_knight` 的特权是历史包袱不是设计**。它有贴图纯粹因为 AI 只生成了一张 `player.png`。3D 重平台正是抹平这个特权、把 6 款一起做实的窗口期。

### 1.2 Redesign：皮肤 = 机型 + 武器 profile + 招牌技能

**新定义**：一款皮肤 = 三件事的绑定包。

```
Skin = {
  ...既有配色字段（body/accent/engine/wing/trail/pattern，全部保留不动）,
  hull:   '<机型 id>',      // 决定 3D 剪影
  weapon: '<武器 profile id>', // 决定主武器弹种 + pattern + 缩放表
  skill:  '<技能 id>',      // 决定招牌主动能力
}
```

三条硬性设计约束（贯穿全部 6 款）：

- **C1 · DPS 收敛**：所有机型 **p3 单目标理论 DPS 落在 [17.0, 22.0]**（基线 21.4 的 −20% ~ +3%）。差异**只准体现在「命中条件」**（距离 / 站位 / 目标数 / 弹速），**不准体现在数值上限**。这是防主导策略的第一道闸。
- **C2 · 技能职能不重叠**：6 个技能按「输出 / 生存 / 资源 / 群体」四象限分布，不许两款技能是同一件事的强弱版。
- **C3 · 剪影唯一**：任意两款机型的黑色剪影并排放置，1 秒内必须能区分。判据是**质量分布 + 轮廓拓扑**（有没有腿 / 是不是中空 / 长宽比），不是细节多寡。

#### ① 苍蓝骑士 `cyan_knight` — 基准截击机

| 项 | 内容 |
|---|---|
| **定位** | 教学 / 万金油。玩家的「零假设」机型，一切平衡的原点 |
| **① 机型剪影（3D 建模用）** | **经典单座后掠翼三角截击机**。长宽比 **1 : 1.30**（长 = 纵向）。机首为尖锐单锥，座舱泡位于机身前 1/3 处、微微隆起；主翼从机身中段向后掠出 45°，翼尖切平；**双垂尾外撇 20°**（不是单垂尾——这是它与其他机型最快的区分点）；尾部两具并排圆形喷口。机腹中线有一枚可见的浅弹舱凸起。**没有任何外挂物**，表面干净。整机质量分布均匀偏前。 |
| **② 配色基调** | `body #3d8ba3`（hue ≈ 193 冷青）/ `accent #cfe7ee` / `engine #e0a06a` / `wing #274d5c` / `trail #8fd4e0`（hue ≈ 190，落在玩家色带 175–200 内）。**全阵容唯一严格落在玩家色带正中的机体**，是玩家识别「这是我」的锚点 |
| **③ 武器 profile** | `weapon: 'dot'` —— **完全等同现状，一字不改** |
| | 发射 pattern：p1→1 发中路；p2→2 发（±8px 平行）；p3→3 发（中 1 直 + 左右各 1 带 ∓1.5 横速）；p4→5 发（中 1 + ±1 + ±2.5 横速）；p5→5 发（中路扇，横速 −3.2/−1.6/0/1.6/3.2） |
| | 单发伤害 **1.00**；弹速 −11 ~ −12 px/step；半径 4 |
| | **p3 理论 DPS = 3 × 1.00 × 7.14 = 21.40** |
| **④ 招牌技能** | **超载齐射 `skill.overdrive`** |
| | 效果：**2.0s（120 逻辑步）内 `shootInterval × 0.60`**（140→84ms，射速 +67%）。弹型 / 伤害 / pattern 全不变，只加快节拍 |
| | 充能来源：通用（击杀 + 擦弹，见 §4.1），`costMul = 1.20` |
| | 与既有系统交互：**与散射枪（G 道具）叠加**（散射覆盖 pattern、超载改间隔，两者正交）；**不消耗 bombs**；持续期间机身尾焰双层加长、机腹弹舱开启——视觉读数在机身而不在 HUD |
| | 单 Boss 有效伤：p3 ≈ **+28.7**，p5 ≈ **+47.8** |
| **⑤ 平衡说明** | 这是唯一**随 power 线性放大**的技能：低 power 时它是「小加速」，p5 时它是「大爆发」。这条曲线刻意与紫电（定值 38.4 伤）反向——**低 power 玩家用紫电更划算，高 power 玩家用苍蓝更划算**，形成机型间的非支配关系而不是强弱序。costMul 1.20 使其在 p5 的爆发被更长的攒槽时间抵消。不引入任何新弹种、新判定，是全阵容风险最低的一款 |

### 1.4 自定义皮肤的兜底规则（NaN 防护的设计层对应物）

编辑器产出的 `c_*` 皮肤**没有** `hull/weapon/skill` 字段。三种处理方案：

| 方案 | 内容 | 评价 |
|---|---|---|
| **A（保底，必做）** | 缺字段时一律兜底为 `hull='cyan_knight'` / `weapon='dot'` / `skill='overdrive'` | **必须实现** —— 这是 NaN 红线在设计层的等价物。缺一个字段就掉进未定义分支，是最难查的一类崩 |
| **B（推荐，T2）** | 皮肤编辑器新增三个下拉：机型 / 武器 profile / 技能，让玩家自由组合 | 成本低（三个 `<select>` + 三组 i18n），把「换色 Mod」升级成「组装 Mod」，是本次改动性价比最高的附加值 |
| **C（不做）** | 自定义皮肤禁用武器/技能，强制走 dot | 惩罚创作，与「内置 Mod」定位冲突 |

**锁定：A 必做，B 列入 T2 推荐（需主理人拍板是否本期做）。**

> ⚠ 若采用 B，需重新评估**主导策略风险**：玩家可以组出「紫电激光 + 苍蓝超载齐射」（穿透 × 射速翻倍）。护栏建议：**武器与技能不许自由交叉**，只允许「机型外观自由 + 武器技能作为一个不可拆的绑定包（6 选 1）」。这条护栏必须与 B 一起落地。

### 1.5 技能触发方案与 P1 的取舍结论

**支柱 P1 原文**（母本 §1.2）：
> 本作唯一输入是「手指位置 + 点击放炸弹」。所有新机制必须通过「位置」这一个变量表达。
> ❌ 反例（明令禁止）：聚焦键、切换武器键、格挡键、长按蓄力。

**关键观察**：P1 的四条反例**全部是「模式」** —— 它们都会**在按下期间改变战机的持续状态**（移动速度、弹型、判定），玩家必须**同时管理位置和模式**。这是双通道认知负担，也正是 P1 要禁的东西。

而**炸弹已经是一个离散动作键**（桌面 pointerdown / 触屏 `#btnBomb`），P1 明确把它列在「唯一输入」之内。**炸弹不是模式：按下即刻结算，无持续状态，不改变战机的任何持续语义。**

因此：

| 方案 | 描述 | P1 字面 | P1 精神 | SDT 自主感 | 结论 |
|---|---|---|---|---|---|
| **S1** | **单键情境技能** —— 桌面 `Shift` / 鼠标右键；触屏新增 `#btnSkill`（`#btnBomb` 左侧） | ✗ 新增一个输入 | ✅ **不新增模式**，与 bomb 同一交互类（离散脉冲） | ✅ 高 | **推荐锁定** |
| **S2** | **满槽自动触发** —— 攒满即放，零输入 | ✅ 完全合规 | ✅ | ❌ **技能退化为被动 buff**，失去抉择 | 备选 |
| **S3** | **S1 为主 + 设置项「技能自动释放」** —— 桌面默认关、触屏默认开 | 部分 | ✅ | ✅ | **可访问性补丁，建议随 S1 一起做** |

**锁定结论：S1 + S3。**

**取舍陈述（明确记录，避免后人反复讨论）：**

- **偏离了什么**：P1 字面上的「唯一输入是位置 + 点击」被破坏，输入动作从 2 个增加到 3 个。
- **守住了什么**：① 新增的是**脉冲**不是**模式** —— 按下即结算，不存在「按住期间战机不一样」的状态；② 玩家全程只需要管理**位置**这一个连续变量，技能键与移动**不冲突**（Shift 不参与 WASD 组合，右键不参与 pointermove）；③ 触屏侧 `#btnSkill` 与已有 `#btnBomb` 完全同构，认知成本为零。
- **换来了什么**：把「皮肤选择」从假决策变成真决策；给 P3（贪婪旋钮）一个可主动兑现的出口；`stealth` 的资源循环玩法在 S2（自动）下**根本无法成立**（自动释放无法选择「何时钻进弹幕」）。
- **成本**：`core.js` 需新增 Shift/右键监听（不进 `KEY_MAP`，独立处理，只在 `state===PLAYING` 生效）；`index.html` 需新增 `#btnSkill`；`hint` 与 `menu.howto` 两条 i18n 文案需更新。
- **⚠ 这是本文档唯一的支柱偏离，须主理人最终拍板（见 §6.5）。**

**如果主理人否决 S1**：退回 S2（满槽自动），此时须做三处降级：① `stealth` 的「幽影潜行」改为纯被动 3s 无敌（失去资源循环玩法，定位改为"生存特化"）；② `violet` 的「贯穿光矛」自动释放会浪费在 Boss 横向相位错位时，需改为「Boss 位于机首 ±30px 时自动触发」的情境条件；③ 皮肤选择的策略深度下降约一半。**降级方案可行但明显更弱，故推荐 S1。**

## 2. 子弹形态分类（BULLET_KINDS Taxonomy）

### 2.0 总则

- **一套形态库，玩家弹与敌弹共享**。同一种形态在两侧语义相同、配色相反（玩家侧冷青 175–200，敌侧琥珀红 12–24）。
- **形态是"弹长什么样 + 怎么飞"，不是"发射多少发"**。发射数量 / 角度分布属于 **pattern**，是 profile 的另一维（见 §2.5 澄清）。
- **所有形态复用既有 `bullets` / `ebullets` 两条池，禁止新建池**（S18 硬门）。
- **所有弹道数学在 `step()` 内、由逻辑步驱动**，渲染层（无论 Canvas2D 还是 Three.js）**只读位置不算位置**（S16 硬门）。

### 2.1 `dot` —— 基准点弹

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | **短胶囊 / 发光椭球**，长轴对齐速度方向，长径比约 2.2 : 1。玩家侧：核心白热、外层冷青自发光壳，尾部拖一条长度 ≈ 3 倍弹长的渐隐能量带。敌侧：**实心球体 + 一圈暗色 rim（`rgba(26,10,4,0.85)`）** —— rim 是敌弹的形状签名，色盲玩家靠"亮芯 + 暗边"分辨敌我，**3D 化后必须保留**（做法：一层反向法线的暗色描边壳） |
| **行为语义** | 匀速直线；`vx/vy` 恒定 |
| **碰撞注意** | 圆判定，半径 = `r`（玩家 4 / 敌 5–6）。**无任何新增** |
| **使用者** | **玩家**：`cyan_knight`（主）、`crimson_falcon`（霰射的弹体）。**敌**：全部 `aim` / `fan` 弹，全部杂兵 |

### 2.2 `laser` —— 细长穿透

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | **长圆柱发光体，长径比 6 : 1，两端半球封头**。三层结构：内芯纯白（半径 30%）、中层色相自发光（100%）、外层半透明辉光壳（180%，加法混合）。沿速度轴取向。**不做拖尾**（本体已经够长，再加拖尾会读成"一条线"而失去弹的颗粒感）。命中瞬间在接触点产生一个扁平的**冲击圆盘**（面向摄像机） |
| **行为语义** | 匀速直线，速度最快（玩家 −14）；命中后 `pierce--`，`pierce < 0` 才销毁 |
| **碰撞注意** | ⚠ **仍用圆判定**（半径 = `r`，不做胶囊 / 线段判定）—— 改判定形状会波及所有碰撞点，与母本 §8.4「部件伤害用 `dmgMul` 而非新伤害系统」同一取舍逻辑 |
| | ⚠ **跨步重复命中**：弹速 14px/step、敌机判定半径 `w*0.45` ≈ 13–24px，一颗穿透弹会**连续 2–4 步都与同一敌机相交**，若不防护会一发打出 4 次伤害。护栏：命中后置 `b.hitCd = 3`（步），冷却期内该弹跳过全部判定 |
| | ⚠ **同步内多目标命中是期望行为**（一步内穿过 2 个并排敌机应各计 1 次），`hitCd` 只在**下一步**生效，故需在同一步的内层循环里用「本步已命中集合」区分 —— 简化做法：`hitCd` 在**步末**统一置位，而不是命中当场置位 |
| **使用者** | **玩家**：`violet`（主武器）、`crimson_falcon`（灼焰突刺的射流弹体，短版）、`violet`（贯穿光矛，`kind='beam'` 变体）。**敌**：现有 `sniper` 弹（白亮长条）**正式归入本类**；建议 `sentinel` P2 的 `wallShot` 弹体升级为短 laser（更凌厉，与其"机甲"母题一致） |

### 2.3 `arc` —— 弧波光带

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | **弯曲的光带（ribbon）**。两种可选实现，二选一由 engineering-lead 定：① 沿最近 N 步历史轨迹生成一条 billboard 曲面带（宽度前粗后细、透明度前高后低）；② 3–5 段短胶囊串联近似。带子有明显的**扭转感**（沿轨迹方向缓慢自转），读起来像"一条被甩出去的光鞭"而不是"一串小球" |
| **行为语义** | **每逻辑步旋转速度向量** —— 与既有敌弹 `av` 语义完全一致（`game.js:1972-1977`：`nvx = vx·cos(av) − vy·sin(av)`）。`av > 0` 向右弯、`< 0` 向左弯 |
| **碰撞注意** | ⚠ **仍用圆判定**（弹头位置 + `r`），**不对光带全长做判定** —— 光带是拖影不是本体。这一条必须写进美术验收：**光带的视觉长度不得超过 3 倍弹半径**，否则玩家会认为尾巴也能打人（P2 的「死了知道为什么」被破坏） |
| | ⚠ 玩家弹需在 `mkBullet()` 新增 `av` 字段（默认 0）并在 `addBullet` **无条件重置**，纪律照抄 `addEbulletEx`（`game.js:206-219`） |
| **使用者** | **玩家**：`stealth`（主武器）。**敌**：现有 `curver` 杂兵、`scorpion` 的 `curveShot`、`void` 的 `vortexShot` 已用 `av`，**全部归入本类**，视觉统一升级为光带 |

### 2.4 `homing` —— 微追踪

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | **微型导弹体**：细长锥形弹身（长径比 3 : 1）、尾部四片小尾翼、尾焰是一小簇快速抖动的火花。拖迹是**螺旋状的细烟迹**（不是直线拖尾）—— 螺旋是"它在自己修正方向"的视觉语义。弹体**朝向必须实时对齐速度方向**（这是 homing 最重要的可读性来源） |
| **行为语义** | 每逻辑步朝目标方向转向，转角受 `turn` 上限约束；`ttl` 到点后转为直线（失去制导） |
| **碰撞注意** | 圆判定不变 |
| | ⚠ **S16 目标选择必须确定性**：按 `game.enemies` **数组序号**遍历取第一个存活目标，**禁止 `Math.random()`、禁止不稳定排序（`Array.sort` 对相等键的顺序在不同引擎下可能不同）**。若必须按距离选，用「遍历取 min，平局取序号小者」的确定性写法 |
| | ⚠ 目标死亡后必须**立即置空并转直线**，否则读到已归还池的对象 → 位置字段是上一颗弹的残留 → 弹会飞向莫名其妙的地方（比 NaN 更难查，因为它不报错） |
| **使用者** | **玩家**：`emerald`（主武器 turn=0.035）、`emerald`（蜂群锁定 turn=0.12）。**敌**：**极度克制** —— P2 明令「追踪到底的必中弹」是反例。仅建议给 `weaverqueen` 的织网追踪弹使用，且硬性护栏：**`turn ≤ 0.02 rad/step` 且 `ttl ≤ 90 步`后必须转直线**，保证任何时刻都存在"跑出制导范围"这个解法 |

### 2.5 `fan` / `spread` —— 扇散（**复合项，语义澄清**）

> ⚠ **重要澄清**：`fan` **不是一种弹形态，而是一种发射 pattern**。它描述的是「一次发射多发、按角度均匀分布」，弹体本身仍是 `dot` 或短 `laser`。
>
> 保留它在 taxonomy 中的位置，是因为现有代码里 `'fan'` 已经是一个 **ebullet kind**（`game.js:2312`，绘制为小菱形），改名会波及既有 Boss 招式表。**折中处理**：
> - **数据层**：`kind='fan'` 保持不变（敌弹的小菱形绘制），视为「dot 的一个视觉变体」；
> - **设计层**：扇散作为 **pattern 维度**记录在武器 profile 里（`crimson_falcon` 的 ±14° × 4 发），不占用 kind 槽位。

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | 敌侧 `fan` 弹体保持**小菱形（八面体）** —— 这是危险带内靠形状区分弹型的既有约定，3D 化后建模为扁平八面体，长轴垂直于速度（横着飞的菱形，与球形的 `aim` 弹一眼区分） |
| **行为语义** | 弹体同 `dot`；扇散语义在发射端 |
| **碰撞注意** | 无新增 |
| **使用者** | **玩家**：`crimson_falcon`（pattern 层）。**敌**：现有全部 `fanShot` / `wallShot` 产物 |

### 2.6 `pulse` / `ring` —— 环爆

| 项 | 内容 |
|---|---|
| **视觉意图（3D 建模）** | **两段式**。飞行期：一颗**表面有同心波纹的脉动球体**（半径随时间做 ±12% 的正弦呼吸，波纹从中心向外滚动）—— 呼吸频率就是"还有多久炸"的读数。爆发期：球体瞬间塌缩，随即展开一个**快速扩张的扁圆环（torus）**，环截面细、扩张速度快、透明度随半径线性衰减，0.25s 内完成 |
| | 敌侧现有 `ring` kind 是**空心环**（`game.js:2342-2344`），3D 化建模为**细环 + 中空**，与实心球的 `aim` 弹形成最强的形状对比 |
| **行为语义** | 飞行段同 `dot`（可带 `ttl`）；`ttl` 归零或命中时触发一次范围判定 |
| **碰撞注意** | ⚠ **环判定是"一次性瞬时"的**，不是持续区域 —— 在触发的那一逻辑步遍历一次敌机列表，之后环只是视觉。这样零新增持续判定实体，S18 无压力 |
| | ⚠ **不与直击伤害叠加**：直击已计伤的目标在本次环爆中跳过，否则贴脸射击会得到双倍伤害 → `golden` 的 17.1 DPS 会在贴脸时变成 34，主导策略成立 |
| | ⚠ 环的视觉复用 `game.rings` 池（cap 96）；`golden` 的圣裁连爆一次占 5 格，需确认与 bomb（`addRing` 1 格）、Boss 死亡特效并发时不超 96 |
| **使用者** | **玩家**：`golden`（主武器 + 圣裁连爆）、`stealth`（潜行结束环爆）。**敌**：现有 `ringShot` 产物；建议 `carrier` 的 `splitVolley` 母弹视觉升级为 pulse（飞行中鼓胀 → 分裂），把"它要裂了"做成可读预告，直接强化 P2 |

### 2.8 玩家弹结构扩展（须由 engineering-lead 落地）

现有 `mkBullet()` 只有 9 个字段。新增以下字段，**全部给安全默认值**（NaN 红线），并在 `addBullet()` 中**无条件重置**（纪律照抄 `addEbulletEx`）：

```
kind:   ''      // 形态标识，'' 等价于 dot（保证旧调用路径行为逐位不变）
dmg:    1       // 单发伤害，默认 1 == 现状
pierce: 0       // 剩余穿透次数，0 == 命中即销毁 == 现状
hitCd:  0       // 命中冷却步数
av:     0       // 每步角速度(rad)，0 == 直线 == 现状
ttl:    0       // 寿命步数，0 == 不限（由出界回收） == 现状
blastR: 0       // 环爆半径，0 == 无环爆 == 现状
target: -1      // homing 目标索引，-1 == 无制导 == 现状
```

> **★ 安全阀**：这一步落地后，**在不改任何调用方的前提下**，冒烟必须与改动前**逐位一致**（125/125）。若不一致，说明某个默认值不等价 —— **停手先修，不要往前堆**（母本 §8.5.4 第 4–5 步同一纪律）。

伤害口径同步修改：`en.hp--` → `en.hp -= (b.dmg > 0 ? b.dmg : 1)`；`b.hp -= dmgMul` → `b.hp -= (b.dmgMul > 0 ? b.dmgMul : 1) * (bu.dmg > 0 ? bu.dmg : 1)`。**两处都要护栏，不许裸读。**

## 3. Boss 视觉辨识度（7 款强区分造型）

### 3.1 现状诊断：模板在哪里

复核 `entities.js:853-1280` 的 7 款 `BOSS_SHAPES` 后，结论是**它们的差异化其实做得不差**（蝎有尾螯、母舰有机库、核心有环、幻影是晶体、虚空有岩甲、织网者有丝线），但玩家仍觉得辨识度低，原因有三：

1. **共用同一套辉光语法**。7 款全部走 `glowHue(hue, 54/60, 68/66, 68/78)` 三组固定色槽 + `p.chargeGlow` 驱动的核心发光。视觉签名被"同一种发光方式"抹平了。
2. **质量分布高度雷同**。除 carrier（190×76）外，其余 6 款的 w/h 都在 132–150 × 92–132 之间，**都是"一个居中的大块 + 周边挂件"**。剪影的第一眼信息（大块在哪、有多大）几乎相同。
3. **`sentinel` 仍复用通用 `boss.png` 贴图**（母本 §8.4 的历史取舍），它是玩家见到的**第一个 Boss**，直接给整个阵容定了"都长差不多"的调。

**3D 重平台的核心任务不是加细节，是拉开质量分布与拓扑。** 下面 7 款每一款都指定了一条**拓扑级的唯一特征**（有腿 / 中空 / 不对称 / 黑核 / 分离体 / 织轮 / 人形），这 7 条互不重叠。

## 4. 技能 / 武器与既有系统整合

### 4.1 技能充能系统（新增，最小侵入）

**新增 `game` 字段**（全部在 `startGame()` 复位，与既有 `graze/combo` 同段）：

```
skillMeter:     0     // 当前充能 [0, costMul]
skillLockUntil: 0     // 防连点锁（逻辑时钟 ms）
skillT:         0     // 技能持续剩余步数（超载/潜行/突刺用）
skillKind:      ''    // 当前生效的技能 id（''=无）
skillWaves:     [×5]  // 圣裁连爆的定长波次表（常驻，只改字段不 new）
```

**充能公式**（全部在 `step()` 内，S16 安全）：

| 来源 | 增量 | 挂载点 |
|---|---|---|
| 击杀敌机 | `+0.028` | `onEnemyKilled()` |
| 擦弹 | `+0.010` | `game.js:2013` 的 `game.graze++` 之后（与 `grazeTotal++` 同段） |
| 连击修正 | `× (1 + min(combo, 30) × 0.01)`，上限 ×1.30 | 上述两处统一乘 |
| Boss 击破 | `+0.30` | `onBossKilled()`（一次性小奖励） |

**充能节奏校准**（对齐既有擦弹加成的 15–28s 节奏）：

| 场景 | 主要来源 | 速率 | 攒满 `costMul=1.0` 耗时 |
|---|---|---|---|
| 杂兵波 | ~1.4 kills/s × 0.028 | 0.039/s | **≈ 26s** |
| Boss 战 | ~4 graze/s × 0.010 | 0.040/s | **≈ 25s** |
| Boss 战 + 高连击 | ×1.2 修正 | 0.048/s | **≈ 21s** |
| `costMul=1.30`（violet） | — | — | **≈ 27–34s** |

> 一场 Boss 战（p3 约 20–30s，p5 约 8–12s）能吃到 **1–2 次**技能；整关（3 波 + Boss）约 **3–4 次**。与擦弹加成同频，不会互相淹没。

**释放条件**：`skillMeter >= costMul && now >= skillLockUntil && state === PLAYING`。释放后 `skillMeter = 0`、`skillLockUntil = now + 500`。
**上限钳制**：`skillMeter = min(skillMeter, costMul)` —— **禁止囤积**（否则玩家会攒到 Boss 战连放两次，破坏节奏）。

### 4.2 与既有三系统的关系

| 系统 | 关系 | 理由 |
|---|---|---|
| **bomb（炸弹）** | **完全独立**。技能不消耗 `game.bombs`，bomb 不影响 `skillMeter` | 职能分离：bomb = 「清屏保命」（消耗品、稀缺、可囤积到 9），技能 = 「输出/位移/资源」（再生资源、不可囤积）。两者永不互为替代品，玩家不需要做"该用哪个"的比较决策 —— **这是防认知过载的关键** |
| **graze（擦弹）** | **单向加挂**。擦弹同时给 `grazeMeter`（既有，不改 `GRAZE_GAIN=0.012`）和 `skillMeter`（新，+0.010）。`stealth` 潜行期两者均翻倍 | **绝不修改 `GRAZE_GAIN`** —— 既有的 84 次满槽平衡是调过的，动它会连带影响分数曲线。新系统另开一路加数，零回归风险 |
| **combo（连击）** | 作为充能**乘数**（×1.0 ~ ×1.30） | combo 现有唯一作用是分数倍率（`game.js:1590`）。给它第二个出口，提升其存在感，且不改既有分数公式 |

### 4.4 HUD 指示 · DOM id 与 i18n 键（S1/S17 硬门）

## 5. 迁移与质量门注记

### 5.1 本文档与 3D 重平台的边界

- 本文档产出的是**渲染无关的玩法 + 视觉蓝图**。§1.3 的「机型剪影」与 §3.2 的「Boss 剪影」段落即 **3D 建模的验收标准** —— 建模完成后应能用这些描述逐条核对（长宽比对不对、特征件在不在、拓扑唯一性守没守住）。
- **Three.js 网格 / 材质 / 光照 / 后处理由 engineering-lead 在 3D 重平台架构中定义**，本文档不作规定。
- 唯一的跨层硬要求：**逻辑层与渲染层的分界不得移动**。所有位置 / 弹道 / 碰撞 / 充能数学留在 `step()`，渲染层（无论 Canvas2D 还是 Three.js）**只读取不计算**。

### 5.2 S16 · 确定性（六档刷新率逐位一致）

| 检查项 | 要求 |
|---|---|
| 所有 `Math.random()` | 必须落在 `step()` 内。本文档新增的**全部机制均为零 RNG**：homing 目标按数组序号、圣裁目标按数组序号、技能充能是确定性累加 |
| 弹道驱动 | 一律按**逻辑步**（不读 `performance.now`、不乘 `dt`）。`av` 旋转、`ttl` 递减、`hitCd` 递减、`skillT` 递减全部是整数步计数 |
| 渲染层 | **零 RNG**。3D 层的粒子抖动 / 材质动画 / 环旋转一律用 `drawBoss` 传入的确定性渲染时钟 `now`（`rt`），**禁止 `performance.now()`、禁止 `Math.random()`** |
| ⚠ 3D 特有新风险 | Three.js 的粒子系统 / 后处理若内部使用随机种子，即使不影响逻辑也会污染截图比对类测试。**须 engineering-lead 确认 S16 的比对口径是"逻辑状态"还是"渲染输出"** |
| 验证 | `rg "Math\.random" src/` 后逐处确认调用点在 step 路径内 |

### 5.3 S18 · 对象池零扩容（`grown === 0`）

| 场景 | 每次发射弹数 | 发射间隔 | 同屏峰值 |
|---|---|---|---|
| 现状 p5 + 2 僚机 | 7 | 140ms | ≈ 56 |
| 现状 p5 + 2 僚机（高波次 95ms） | 7 | 95ms | ≈ 82 |

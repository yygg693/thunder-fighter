# 打飞机 · 商用化重构方案

> 版本：v1.0 ｜ 日期：2026-07-27 ｜ 状态：待评审
> 目标：把当前"能玩的 Demo"重构为"可上架、可运营、可持续迭代"的商业产品。

---

## 0. 执行摘要（TL;DR）

当前项目是一个 ~2,400 行的纯 Canvas + 原生 JS 小游戏，玩法完整（4 关战役 / 4 Boss / 皮肤系统 / BGM / 排行榜），但工程形态是"原型级"：无构建、无类型、无测试框架、逻辑/渲染/UI/数据高度耦合。**直接上架风险很高，但不值得推倒重写**——渲染与玩法代码质量不差，真正缺的是**工程化骨架**和**发行管线**。

**推荐路线：自研引擎保留 + TypeScript 渐进重构 + 数据驱动内容管线 + 多平台打包发行。**

- 第 1 阶段（2 周）：工程化地基（Vite + TS + 模块化 + 测试 + CI）
- 第 2 阶段（2 周）：架构分层（引擎/玩法/内容/平台四层解耦 + 对象池 + 数据驱动）
- 第 3 阶段（2 周）：内容扩充与打磨（关卡配置化后量产、新手引导、数值平衡）
- 第 4 阶段（2 周）：发行准备（Tauri 桌面包 / 微信小游戏适配 / 商店物料 / 合规）

**8 周达到可上架状态**，先行平台建议 **itch.io + Steam（海外）**，国内商业化务必先解决**版号**问题（见 §7）。

### 2.2 产品定位

- **一句话卖点**："触摸板/鼠标指哪打哪的零上手门槛弹幕射击"——操作差异化是核心记忆点，商店页第一屏必须体现。
- **内容纵深**：现 4 关偏短（~15 分钟通关）。商用版目标 **8–10 关 + 无尽模式 + 每日挑战**，支撑 3–5 小时主线 + 重复游玩。
- **变现钩子**：皮肤 Mod 系统是天然的 DLC/内购点（涂装包、特效包），本体买断 + 皮肤 DLC 是最稳的组合。

## 3. 目标架构

### 3.1 技术选型：自研 vs 引擎

| 方案 | 优点 | 缺点 | 结论 |
|---|---|---|---|
| **A. 保留自研 Canvas 内核 + 工程化**（推荐） | 现有 2400 行渲染/玩法代码全部保住；零运行时依赖；包体 <1MB（Web）；团队已熟悉 | 需自己补齐场景管理/对象池等基础设施 | ✅ 采用 |
| B. 迁移 Phaser 3 | 生态全（场景/物理/相机/输入现成） | 重写全部渲染与玩法（~2 周纯搬运）；包体 +1MB；学习成本 | ❌ 推倒代价大于收益 |
| C. PixiJS（只换渲染层） | WebGL 渲染性能上限高 | 玩法逻辑照样要自己管；当前 Canvas 性能在弹幕量级下远未触顶 | ⏸ 后续性能不够再换，接口预留 |

**决策：方案 A**。当前 Canvas 2D 在 ~500 个同屏对象下毫无压力（弹幕游戏量级），自研内核够用；把省下的引擎迁移成本投到内容和发行上。渲染层预留 `IRenderer` 接口，未来可平替 PixiJS/WebGL。

### 3.2 分层架构

```
┌─────────────────────────────────────────────────┐
│ platform/          平台适配层（差异全关在这里）      │
│  ├─ web/         浏览器 + PWA                     │
│  ├─ desktop/     Tauri 壳（Steam/itch.io）        │
│  └─ wechat/      微信小游戏适配（canvas/音频/存储） │
├─────────────────────────────────────────────────┤
│ content/           内容层（纯数据，策划可改）        │
│  ├─ stages/*.json    关卡/波次/Boss 配置          │
│  ├─ enemies/*.json   敌机数值表                   │
│  ├─ skins/*.json     皮肤包（含 DLC 校验）         │
│  └─ i18n/{zh,en}.json  语言包                    │
├─────────────────────────────────────────────────┤
│ game/              玩法层（规则，与渲染无关）        │
│  ├─ scenes/      Menu/Playing/Pause/Victory 场景  │
│  ├─ systems/     生成/碰撞/波次/道具/存档系统      │
│  ├─ entities/    玩家/敌机/子弹/Boss 行为         │
│  └─ data/        存档抽象（版本迁移+云同步接口）    │
├─────────────────────────────────────────────────┤
│ engine/            引擎层（与具体游戏无关，可复用）  │
│  ├─ core/        主循环(固定步长)/场景机/事件总线   │
│  ├─ render/      IRenderer 接口 + Canvas 实现     │
│  ├─ audio/       双总线混音 + 程序化合成器         │
│  ├─ input/       触摸板/键鼠/手柄 统一抽象         │
│  └─ pool/        对象池                            │
└─────────────────────────────────────────────────┘
```

**核心原则：依赖只允许向下**。`game` 不知道 `platform` 存在，`engine` 不知道 `game` 存在。平台差异（存储、音频解锁、canvas 获取、全屏 API）全部通过依赖注入传入。

### 3.3 关键机制设计

**(1) 主循环：固定时间步长（Fixed Timestep）** — 解决 D8
```
accumulator += realDelta
while (accumulator >= STEP) { update(STEP); accumulator -= STEP }  // STEP = 1/60s
render(interpolation)   // 渲染插值，高刷屏丝滑
```
逻辑恒按 60Hz 跑，144Hz 屏上速度一致、画面靠插值更顺滑。

**(2) 对象池** — 解决 D4
子弹/粒子/敌机/敌弹全部池化（预分配 + 空闲链表），热循环零分配。预估同屏峰值：玩家弹 200 + 敌弹 300 + 粒子 400，池容按 2 倍冗余。

**(3) 数据驱动内容管线** — 解决 D3
```jsonc
// content/stages/stage-02.json
{
  "id": "asteroid-belt", "name": "陨石带",
  "theme": { "bg": "#0d0712", "accent": "#ffb24a", "bgm": "drive" },
  "waves": [
    { "type": "formation", "enemy": "wasp", "count": 8, "pattern": "v-arc" },
    { "type": "boss", "ref": "bosses/mining-scorpion" }
  ]
}
```
策划改 JSON 即可出新关；构建时 schema 校验（zod），坏配置直接 CI 拦截。皮肤包同构，DLC 皮肤 = 加密签名 JSON 包。

**(4) 存档抽象** — 解决 D6
```ts
interface SaveStore { read(): SaveData; write(d: SaveData): void }
// 实现：LocalStorageStore（web）/ FileStore（desktop）/ WxStorageStore（微信）/ SteamCloudStore
```
存档带 `version` 字段 + 迁移链（v1→v2→v3），Steam 云存档接 `FileStore` 目录映射即可。

**(5) 输入抽象** — 顺手补上手柄
`IInput.getAim(): {x, y}` 统一触摸板/鼠标/键盘/Gamepad 四种来源，Steam Deck 即插即用。

## 5. 打包与发行

### 5.1 桌面壳：Electron → Tauri

| | Electron（现状） | **Tauri 2（推荐）** |
|---|---|---|
| 包体 | ~80–150MB（自带 Chromium） | **~8–15MB**（用系统 WebView） |
| 内存占用 | ~200MB+ | ~80MB |
| Steam 集成 | 需 greenworks（维护差） | 有成熟 `tauri-plugin-steamworks` 方案 |
| 风险 | 无 | Windows 依赖 WebView2（Win10+ 预装） |

**决策：换 Tauri 2**。小游戏配大壳是本末倒置，8MB 安装包对下载转化率是实打实的提升。CI 已有基础，改造成本约 1 天。若求稳妥可先保留 Electron 兜底，Tauri 跑通后切换。

## 7. 合规红线（商用前必须处理）

1. **版号（国内付费）**：在中国大陆上架并内购/买断收费，需取得**游戏版号**（审批周期 6–12 个月+）。规避路径：只发海外（Steam/itch.io 全球版不受限）、国内只做免费+广告（微信小游戏广告变现当前不强制版号，政策以届时为准）。
2. **软件著作权**：上架国内平台/应用市场必备，尽早申请。
3. **隐私合规**：接入任何统计/广告 SDK 即需隐私政策页 + 用户同意弹窗；Steam 也要 GDPR 声明。方案默认：**首发版本零联网、零采集**，Sentry 等监控做成可选开启。
4. **字体/素材版权**：当前全程序化生成无版权风险；后续若引入字体（如站酷/思源）确认 SIL OFL 许可；商店美术外包需签版权转让。
5. **名称商标**：「打飞机」类目通用词难注册，建议商用版起独立品牌名（如「星轨突击 / Startrail Strike」）并查商标冲突。
6. **未成年人保护**：国内版本需接入实名认证+时长限制（微信小游戏平台自带能力）。

## 10. 不做什么（明确排除）

- ❌ 不迁 Phaser/Unity——推倒重来，收益不抵成本
- ❌ 首发不做联机/全球排行榜——服务端运维成本与体量不匹配，本地排行榜足够
- ❌ 首发不做内购商店——买断制，皮肤 DLC 二期再说
- ❌ 不做移动端原生——Capacitor 套壳等 Steam 验证后再说

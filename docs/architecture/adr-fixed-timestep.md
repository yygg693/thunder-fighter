# ADR-001 · 固定时间步长（Fixed Timestep）与帧率解耦

- **状态**：已采纳（Accepted）
- **领域**：引擎 / 主循环 / 性能
- **关联技术债**：D8（帧率耦合）、D4（无对象池）
- **提出**：eng（工程主理）
- **决策日期**：2026-07-31
- **适用范围**：`src/game.js` 主循环与渲染路径（D8）；`src/game.js` 实体生命周期管理（D4）

---

## 1. 背景与上下文（Context）

「雷霆战机」是一款纯 HTML5 Canvas + 原生 JS 的纵版弹幕射击游戏，沿用经典 `<script>` 标签 + `window.DJFE` 全局命名空间，**禁止 ES Module / 打包器**，必须 `file://` 双击即可运行。

原主循环（改动前，`tools/.baseline/game.js`）直接以 `requestAnimationFrame` 的回调时间戳 `now` 驱动逻辑，并把 `now` 与帧间差 `dt` 喂给所有 `update*` 函数。这导致**技术债 D8（帧率耦合）**：

- 全部数值平衡（弹速、敌机 `vy`、火力间隔 `shootInterval`、`fireT` 计时、无敌帧 `invulnUntil`）都是按「60fps 下每帧一逻辑步」手工调出来的；
- 一旦显示器是 144Hz / 240Hz，`requestAnimationFrame` 每 6.9ms / 4.2ms 触发一次，逻辑步频随之翻倍，弹速、敌机下落、波次节奏**整体加速**，手感与平衡被悄悄破坏；
- 一旦掉帧（卡顿 / 切后台），逻辑步频下降，弹幕变慢、变稀疏，等于变相送命，**高刷变快、低刷变慢**——这是本工作流的硬红线之一，任何解法和手感不允许改变。

与之并存的**技术债 D4（无对象池）**：热循环里大量 `arr = arr.filter(...)` 和 `push({...})` 每帧新建临时数组与对象字面量，在长局 + 满弹幕下产生显著 GC 压力，是掉帧的诱因之一。

两条技术债在同一轮重构里解决，且**共享同一条不可逾越的红线：行为零变化**。即：在 60Hz 显示器上，重构前后每一帧的逐位状态必须完全一致。

---

## 2. 决策（Decision）

### 2.1 逻辑时钟恒等式（D8 核心）

不改动任何一条数值公式、不缩放任何 `dt`，而是把「逻辑时钟」重新定义为：

```
stepTime(k) = T_ORIGIN + (k * 1000) / HZ        // HZ = 60
```

也就是「**一台永远不掉帧的 60fps 机器上的 `performance.now()`**」。`T_ORIGIN` 取 `performance.now()` 初值，与改动前 `last` 的初值同源；`k` 为已执行的逻辑步序号（`game.runFrames`）。

主循环改用**固定步长累加器（Fixed Timestep Accumulator）**：

```
每帧:  acc += 真实经过时间(ms)            // 经过 STEP*MAX_CATCHUP 则截断，杜绝死亡螺旋
       while (acc >= STEP - ACC_EPS && n <= MAX_CATCHUP) {
         prevT = stepTime(k);  k++;  tNow = stepTime(k);
         snapshot();  step(tNow, min(tNow - prevT, 50));  starSteps++;
         acc -= STEP;  n++;
       }
```

于是喂给 `step(now, dt)` 的 `now` / `dt` 与改动前 60fps 下逐位相同（`stepTime(k) - stepTime(k-1) ≡ 1000/60`），`shootInterval` / `fireT` / `invulnUntil` 等全部原样保留，逻辑层一行公式未动。

### 2.2 渲染外插（Extrapolation），而非插值（Interpolation）

逻辑固定 60Hz，显示器若 144Hz，同一帧状态会被重复显示 2~3 次，出现规律性抖动。采用**外插**而非教科书式插值：

```
renderAlpha = clamp(acc / STEP, 0, 1)            // 帧内余量，60Hz 下 α≈0
渲染前: x += (x - px) * α      (px = 上一步的位置快照)
渲染后: 还原 x
```

选择**外插**的理由（被否决插值）：插值需拿 `(px, x)` 往回取样，会引入整整一步（16.7ms）的显示延迟——本期是「手感」工作流，红线是手感不许变。外插在 `α=0`（即 60Hz）时恒等于当前位置，零延迟、且与改动前逐位一致。

代价：实体**骤然变向**的那一帧会有不足一步的过冲，短促不可察（见 §5 风险）。

实现上，外插坐标写在 `x/y` 上、`render()` 后立即还原，**绝不污染逻辑状态**，也**不改动 `entities.js` 的任何绘制函数**（红线之一）。

### 2.3 对象池 + 原地稳定压缩（D4）

两件事同时做，目标热循环零分配：

1. **实体对象预分配复用**：`Pool` 预分配 `cap` 个对象，`get()` 从自由栈取、`put()` 还回，取代 `push({...})` 的每帧新建；
2. **原地稳定压缩取代 `arr = arr.filter(...)`**：`sweep(list, pool, keep)` 在原数组内把存活元素前移、保证**原有顺序不变**（顺序影响碰撞判定次序，必须一致），被清除的元素归还对象池。

池被取空时不丢内容、改为临时新建并计入 `grown`——**宁可多分配也不改变行为**；`grown > 0` 会在 `poolStats()` 与性能 HUD（F3）上报警，提示容量该调大了。

### 2.4 关键常量

| 常量 | 值 | 含义 |
|---|---|---|
| `HZ` | `60` | 逻辑频率，数值平衡基准 |
| `STEP` | `1000/60` | 单步逻辑时长 (ms) |
| `MAX_CATCHUP` | `5` | 单帧最多补算 5 步（≈83ms），多余时间直接丢弃，杜绝追帧雪崩 |
| `ACC_EPS` | `1e-6` | 累加器容差（1ns）：吸收 rAF 时间戳浮点噪声，避免整步被误判「差一点点」漏步 |
| `T_ORIGIN` | `performance.now()` | 逻辑时钟原点 |

## 3. 后果（Consequences）

**正面：**

- **行为零变化得到证明**：60Hz 下 `stepTime(k)` 与改动前 `now` 逐位相同，逻辑层全部公式未动。
- **帧率解耦**：逻辑步频恒为 60Hz，不再随显示器刷新率漂移；高刷只换来更平滑的渲染外插，不加速、不减速。
- **GC 压力结构性下降**：热循环不再每帧新建临时数组 / 对象字面量。
- **可观测**：性能 HUD（F3）实时显示 FPS / step / render 耗时与 6 个池的水位、扩容告警。

**负面 / 代价：**

- 高刷下实体骤然变向时有一帧不足一步的视觉过冲（§5，已评估为可接受）。
- 引入 `snapshot()`（每逻辑步对所有活动实体做 `px/py` 标记）与渲染前/后外插还原的额外遍历，属 O(实体数) 的轻量开销。
- 主循环复杂度上升（累加器 + 外插 + 还原），需通过 `tools/verify.js` 的四柱校验守住行为红线。

## 4. 被否决的替代方案（Alternatives Considered）

| 方案 | 简述 | 否决理由 |
|---|---|---|
| **A. 硬锁帧（rAF 节流到 60Hz）** | 用定时器把渲染锁在 60fps | 治标不治本：高刷屏仍按 60 渲染（浪费硬件）、低刷/掉帧仍变慢；且锁帧会引入输入延迟与卡顿观感，违背「解耦」初衷。 |
| **B. 缩放 dt（dt-aware 物理）** | 把 `dt` 按真实帧时长缩放，让运动与墙钟时间对齐 | 直接破坏数值平衡：所有按「每帧一增量」调好的弹速/`vy`/`fireT` 都要重调，且浮点累加 `now` 与 60fps 基准不再逐位一致，**违反行为零变化红线**。 |
| **C. 墙钟时间驱动 + 重调平衡** | 改用真实运行秒数驱动，全量重做数值 | 工作量巨大、回归风险高，且重调后的「平衡」仍无法保证与改动前逐位一致——红线不允许任何可见的手感偏移。 |
| **D. 教科书式插值（Interpolation）** | 渲染取 `(px, x)` 中间点 | 引入一整步（16.7ms）显示延迟，手感变「肉」，本期手感工作流不可接受；选外插 `α=0` 时恒等于改动前，零延迟。 |
| **E. 每帧新建 + 仅做 GC 调优** | 保留 `filter`，靠分代调优缓解 | 治标不治本；弹幕长局下分配量随存活实体线性增长，无法根除 GC 抖动，且违背 D4 的「热循环零分配」目标。 |

→ 最终采纳 **固定步长累加器（逻辑时钟恒等式） + 外插 + 对象池**，是唯一同时满足「帧率解耦」与「行为零变化红线」的组合。

## 5. 风险与缓解（Risk & Mitigation）

| 风险 | 严重度 | 缓解 |
|---|---|---|
| 高刷下实体骤变向时外插过冲（不足一步） | 低 | 仅 1 帧、短促不可察；逻辑判定不受影响（外插坐标渲染后即还原）。后续若高刷玩家反馈，可加 `interpOn=false`（已预留开关）或改插值。 |
| 极端卡顿 / 切后台导致 `frameDt` 巨大 | 低 | `MAX_CATCHUP=5` 截断 + 累加器兜底清 0，宁可掉速也不做追帧雪崩 / 卡死。 |
| 对象池容量不足（满弹幕长局） | 低 | 压测已验证各池水位舒适、`grown=0`；`grown>0` 会报警，必要时上调预分配 `cap`。 |
| **V8 浮点未装箱回退（GC 回归陷阱）** | 中 | 见下方「实现陷阱」，已在 `drawBackground` 星点循环处规避。 |

### 实现陷阱：V8 未装箱浮点（Unboxed Double）回退

固定步长 + 对象池本身把分配降为零，但一处**看似无害**的重构曾把 GC 收益整个吃掉，值得记入 ADR：

原 `drawBackground` 的视差星点循环是「位移 + 绘制」合一的同一趟 `for...of`。最初为解耦「位移（按逻辑步）」与「绘制（每帧）」，我把**位移拆成独立的一趟遍历**——结果 V8 无法再把 `s.y` 保持在未装箱的浮点寄存器里，每次读写 `s.y` 都要新建一个 `HeapNumber`。180s 长局凭空多出约 45MB 垃圾，完全吞噬对象池省下的量。

**修复**：位移与绘制留在同一趟遍历（仅「补步」`starSteps>1` 的追帧步走独立循环，最后一步与绘制融合）。`Math.random()` 调用次序在两条分支下都是「每一步按 `stars` 顺序遍历一遍」，与改动前完全一致，行为零变化不被破坏。

**经验法则**：热循环里对同一数值字段的「读-改-写」必须留在**同一趟遍历内**，否则可能因跨遍历打断 V8 的 unboxed-double 优化而引入隐蔽的分配回归。此类回归用 `--trace-gc-nvp` 的 `allocated` 字节数（而非 GC 次数）才能稳定测出；堆采样器（`--heap-prof`）只统计存活对象，对本类垃圾问题无效。

## 6. 验证与可追溯性（Verification & Traceability）

行为零变化与性能收益由 `tools/verify.js`（开发工具，不随游戏发布）的四柱校验证明，基线 `tools/.baseline/`（改动前 `src` 快照）对照当前 `src/`：

| 校验 | 命令 | 证据 | 结论 |
|---|---|---|---|
| **parity** 行为一致性 | `node tools/verify.js parity` | 18 个场景（恒定 `rand`×5 + 种子 `PRNG`×4，survivor/mortal 双输入），逐帧全量状态 FNV-1a 签名逐位一致 | 行为零变化 ✓ |
| **refresh** 跨刷新率一致性 | `node tools/verify.js refresh` | 30/60/72/120/144/240Hz 下逻辑步数 1798~1800 一致；且各刷新率与 60Hz 逐采样点状态完全一致；墙钟 20s 进度各刷新率一致 | D8 已修复 ✓ |
| **alloc** 热循环零分配 | `node tools/verify.js alloc` | `filter/map/slice/concat` 新建数组 105453→0（100% 消除）；运行期实体新建 10061→0，仅启动预分配 3200；池压测 5 种子×300s hard 水位舒适、`grown=0` | D4 已修复 ✓ |
| **gc** 真实 GC 压力 | `node tools/verify.js gc` | 子进程 `--trace-gc`，新生代回收字节数中位数；current 垃圾总量 ≤ baseline×1.02（星点循环修复后 current 低于 baseline） | GC 未变差 ✓ |

> 注：无头环境下 `render` 里的字符串/样式赋值两版相同，会稀释对象池收益；**确定性的分配消除量以 `alloc` 的计数为准**，`gc` 项判定放宽为「不变差即通过」。

运行 `node tools/verify.js all` 一次性跑齐四柱，全绿即代表 D8 + D4 重构满足「行为零变化」红线。

## 7. 关联方与约束

- **不得改动**：`src/entities.js` 任何绘制函数、`src/core.js` 音频、`src/entities.js` 数值平衡与关卡设计。
- **不得**：ESM / 打包器 / 任何破坏 `file://` 双击可玩的改变；`git commit` / `git push`（交付前需人工审批）。
- **可观测句柄**：`window.DJFE.__debug`（逻辑状态、`poolStats()`、`player.invulnUntil` 等），供 `verify.js` 与性能 HUD 读取。
